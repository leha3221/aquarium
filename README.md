# Информационная система сервиса обслуживания аквариумов

Вариант: **Заявка на обслуживание аквариума**.

## Предметная область
Сервис принимает заявки клиентов на обслуживание аквариумов. Для каждой заявки хранится клиент, адрес, тип обслуживания, тип аквариума, дата создания/плановая дата, стоимость и статус.

## Сущности
- `Client` — клиент сервиса.
- `ServiceRequest` — заявка на обслуживание аквариума.

Связь: `service_requests.client_id -> clients.id`.

- Aquarium — аквариум клиента.
- Fish — группа рыб одного вида в аквариуме.

## Требования КР1
Реализованы:
- CRUD для клиентов, заявок, аквариумов и рыб;
- `enum` для статуса, типа обслуживания и типа аквариума;
- интерфейс `Exporter` и полиморфные реализации Excel/CSV;
- собственные исключения;
- 5+ бизнес-правил;
- 2+ поиска;
- 2+ фильтра;
- 2+ сортировки;
- статистика из 5+ показателей;
- JDBC: `Connection`, `PreparedStatement`, `ResultSet`, try-with-resources;
- PostgreSQL;
- Excel `.xlsx` и CSV;
- многослойная архитектура `Console UI -> Service -> Repository -> Database`.

## Запуск
Для JavaFX-клиента установите JDK 17+, Maven и Docker Desktop с Docker Compose. Создайте локальный `.env` и запустите PostgreSQL:

```powershell
Copy-Item .env.example .env
# Измените POSTGRES_PASSWORD в .env
docker compose up -d --wait
```

JavaFX автоматически читает учётные данные и порт из локального `.env`. В PowerShell запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-javafx.ps1
```

`mvn exec:java` запускает консольное приложение КР №1. Полные инструкции и возможности JavaFX описаны в [docs/JAVAFX_RUN.md](docs/JAVAFX_RUN.md).

## Защита
Главная идея архитектуры:
`Console UI -> Service -> Repository/JDBC -> PostgreSQL`

SQL-запросы находятся в Repository, а бизнес-правила — в Service.

## Аквариумы и рыбы
Добавлены Aquarium (клиент, название, тип, объём в литрах) и Fish
(аквариум, вид, количество особей). Fish представляет группу рыб одного вида.
В главном меню: 8 — аквариумы, 9 — рыбы. Для обеих сущностей доступны создание,
список, получение по ID, изменение, удаление, поиск, фильтрация и сортировка.
Статистика включает число аквариумов, записей о рыбах и общее количество рыб.

Связи: clients → aquariums → fish. При удалении клиента удаляются его аквариумы
и рыбы; при удалении аквариума — его рыбы. Проверяются существование владельца
и аквариума, обязательные поля, положительные объём и количество.
Для типа REPTILE размещение рыб запрещено; нельзя сменить тип на REPTILE,
пока аквариум содержит рыб.

Для существующей БД выполните миграцию (сохраняет данные):
    psql -h localhost -p 5433 -U postgres -d aquarium_service -f sql/migration_aquariums_fish.sql
Для новой учебной БД используйте sql/schema.sql. Этот скрипт пересоздаёт таблицы
и добавляет демонстрационные данные; для обновления используйте миграцию.
Порт должен совпадать с DatabaseManager (сейчас 5433).
Заявки сохраняют прежнюю связь с клиентом и тип аквариума.

## Проверка новых сервисов
Тест не требует PostgreSQL и использует репозитории в памяти.
После компиляции запустите с включёнными проверками assert:
    mvn test-compile
    java -ea -cp "target/classes;target/test-classes" ru.mirea.aquarium.EntityServiceTest
Для Linux/macOS разделитель classpath — двоеточие.
